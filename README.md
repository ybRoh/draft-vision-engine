# 제도인식엔진

교재의 패턴 제도 도면 이미지를 읽어 **자동 제도 사양(DSL)** 으로 옮기고, 그것을 실행해 SVG·DXF 도면을 뽑는 엔진이다. 핵심은 이미지를 벡터(좌표)로 따지 않는다는 것이다 — **계산식을 받아쓴다.** 도면에서 좌표를 뽑아내면 그 사이즈에서만 맞는 죽은 그림이 되지만, `B/12+2.5` 같은 교재의 식을 그대로 뽑아 두면 치수 하나를 바꿨을 때 도면 전체가 따라온다. 그레이딩이 따로 만들 것 없이 공짜로 따라온다는 뜻이고, 이 리포의 검증 스크립트 하나(`verify_grade`)는 오직 그 사실만 잰다.

## 빠른 시작

```bash
npm install
```

의존성은 `@anthropic-ai/sdk` 하나뿐이고, 그것도 `tools/extract.mjs`(이미지 인식)에서만 쓴다. 제도 엔진(`lib/`)과 렌더링·검증은 의존성이 0이라 Node 만 있으면 돈다.

예제 두 장을 렌더한다 (`out/bunka-front.svg` · `.dxf`, `out/bunka-back.svg` · `.dxf` 가 생긴다):

```bash
npm run demo
```

치수를 바꿔 다시 렌더한다 — 도면 전체가 따라온다:

```bash
node tools/render.mjs examples/bunka-front.draft.json --set B=98 --set SW=42
```

검증을 돌린다:

```bash
npm test
```

`npm test` 는 검증 스크립트 넷을 순서대로 돌린다 — `verify_expr` → `verify_draft` → `verify_grade` → `verify_dxf`. 각각이 무엇을 지키는지는 [도구](#검증-스크립트-넷) 절에 적었다.

## 파이프라인

```
  교재 도면 이미지 (.png/.jpg)
        │
        │  tools/extract.mjs      Claude Vision + structured output(json_schema)
        │                          "그림을 그려줘" 가 아니라 "제도 절차를 받아써줘"
        ▼
  제도 DSL (out/*.draft.json)     계산식 문자열 그대로. 사람이 읽고 고칠 수 있다
        │
        │  lib/validate.mjs        구조 + 참조 무결성 + 계산식 검사
        │  lib/draft.mjs           식 평가 · 위상정렬 → 실제 좌표
        ▼
  도형 (points · segments · darts · notches · bbox)
        │
        ├── lib/svg.mjs  →  SVG   화면 확인 · 원본 위 겹쳐 보기 (cm 좌표 그대로, 1cm 모눈 + 5cm 자)
        └── lib/dxf.mjs  →  DXF   R12(AC1009) · mm · CAD/CAM 전달용
```

그리고 고치는 루프가 있다:

```
  extract → render → overlay(원본 이미지 위에 결과를 겹쳐 본다)
                        │
                        └─ 어긋난 곳을 draft.json 에서 손으로 고친다 → 다시 render
                        └─ 다 맞춘 짝(이미지 + json)을 examples/fewshot/ 에 넣는다
                                   → 다음 페이지 인식률이 올라간다
```

한 번에 완벽하게 뽑히는 것을 기대하는 도구가 아니다. **모델이 초안을 쓰고, 사람이 오버레이로 재서 고치고, 고친 것이 다음 초안을 좋게 만드는** 구조다.

## DSL 레퍼런스

DSL 은 `draft-spec v1` 이다. 정의는 [`lib/schema.mjs`](lib/schema.mjs) 한 곳에 있고, 그 스키마가 두 군데에서 쓰인다 — `extract.mjs` 는 Claude 의 structured output 스키마로 걸어 모델이 이 모양을 **벗어날 수 없게** 만들고, `validate.mjs` 는 사람이 손으로 쓴 DSL 을 같은 스키마로 검사한다.

> **필드는 전부 필수다.** structured output 제약에 맞추느라 스키마의 모든 객체가 `required: 전체 키` + `additionalProperties: false` 로 되어 있다. `desc`, `closed`, `tension` 같은 것도 생략할 수 없고, `darts`·`notches`·`notes` 도 비어 있으면 `[]` 를 명시해야 한다. 모르는 항목을 하나라도 넣으면 검사에서 걸린다(`toString` 처럼 자바스크립트 객체가 원래 갖고 있는 이름도 예외가 아니다).

`validate()` 가 보는 것은 구조만이 아니다. 스키마를 통과한 뒤에 이어서 이만큼을 더 잰다.

- **참조 무결성** — `segments`·`darts`·`notches` 가 가리키는 점이 `points` 에 실제로 있는지
- **계산식** — 문법(괄호 짝, 빈 식), 식이 쓰는 이름이 measures/params/points 에 있는지, **함수 이름과 인자 수**. 계산해 봐야 아는 것(0 나눗셈 등)만 빼고 식만 봐도 알 수 있는 건 여기서 다 걸러진다
- **id** — 이름 규칙(영문 시작·영문/숫자/밑줄)과 중복
- **선** — 점이 2개 이상인지, 같은 점이 연달아 두 번 나오지 않는지(길이 0 구간), `layer` 가 있는 값인지, `tension` 이 `0~2` 인지
- **빈 도면** — `points` 나 `segments` 가 비어 있으면 오류

계산식 검사가 여기 있는 게 중요하다. 검사기가 식을 안 보면 `extract.mjs` 의 "고쳐 달라" 재시도가 아예 안 돌고, API 를 한 번 다 쓴 뒤 `resolve` 단계에서 스택트레이스로 죽는다.

### 최상위 구조

```json
{
  "version": 1,
  "name": "문화식 계열 상의 원형 앞판",
  "source": { "book": "교재명", "page": "128" },
  "units": "cm",
  "measures": [ ... ],
  "params":   [ ... ],
  "points":   [ ... ],
  "segments": [ ... ],
  "darts":    [ ... ],
  "notches":  [ ... ],
  "notes":    [ "한 줄 메모", ... ]
}
```

| 필드 | 뜻 |
|---|---|
| `version` | 항상 `1` (숫자) |
| `name` | 제도명. 렌더 결과의 제목·DXF TEXT 로 나간다 |
| `source` | `{ book, page }`. 모르면 `"미상"` 을 넣는다 (빈 값이 아니라 문자열이어야 한다) |
| `units` | 항상 `"cm"` |
| `measures` | 인체 치수·기준값 → [아래](#measures-와-params) |
| `params` | 여유분·경사각 같은 제도 상수 → [아래](#measures-와-params) |
| `points` | 점. **제도 순서대로** 쓰는 것이 좋다 |
| `segments` | 점을 잇는 선 |
| `darts` | 다트 (없으면 `[]`) |
| `notches` | 너치·합인 표시 (없으면 `[]`) |
| `notes` | 도면에서 못 읽은 값, 추정한 값, 확신 없는 부분. **모르는 걸 그럴듯하게 채우는 대신 여기 적는다** |

한 파일은 **조각 하나**를 담는다. 앞판·뒤판은 파일 두 개다(예제가 그렇다).

### measures 와 params

둘 다 `{ id, desc, value }` 모양이고 식에서 이름으로 참조된다. 형태가 같으니 **무엇을 어디에 넣느냐가 이 DSL 에서 제일 중요한 판단**이다.

```json
"measures": [
  { "id": "B",  "desc": "가슴둘레", "value": 86 },
  { "id": "WL", "desc": "등길이",   "value": 38 },
  { "id": "SW", "desc": "어깨너비", "value": 39 }
],
"params": [
  { "id": "AHD_ADD",  "desc": "진동깊이 상수 (B/6 에 더함)", "value": 7 },
  { "id": "SH_ANGLE", "desc": "앞 어깨경사(도)",             "value": 22 }
]
```

- **measures = 사람 몸에서 재는 값.** 사이즈가 바뀌면 같이 바뀐다. `B`(가슴둘레) `WL`(등길이) `SW`(어깨너비) `BPL`(유장) 같은 것.
- **params = 치수와 무관한 제도 상수.** 여유분, `B/6+7` 의 `7`, 어깨경사 각도, 다트 벌림. 사이즈가 바뀌어도 그대로다.

도면의 숫자를 식에 그냥 박아 넣지 말고 `params` 로 빼서 이름을 붙이는 편이 좋다. 나중에 "이 7 은 뭐였지" 를 되묻지 않아도 되고, 원형을 응용으로 옮길 때 그 값만 만지면 된다.

두 목록과 `points` 는 **같은 이름공간**을 쓴다. 이름이 겹치면 검사에서 걸린다. `segments`·`darts`·`notches` 의 id 는 도구들이 키로 쓰므로 각각 자기 목록 안에서만 안 겹치면 된다 — 그것도 검사한다. 이름이 `toString` 처럼 자바스크립트 객체의 프로토타입 멤버와 같아도 선언한 값이 이긴다(엔진이 프로토타입 없는 이름표를 쓴다).

값 덮어쓰기(`--set`)는 measures 든 params 든 이름만 맞으면 된다. 없는 이름을 덮어쓰려 하면 조용히 무시하지 않고 터진다.

### points — 다섯 가지 지정 방식

모든 점은 `id`, `desc`, `kind` 를 갖고, `kind` 에 따라 나머지 필드가 갈린다. `id` 는 식에서 참조되므로 **영문으로 시작하고 영문·숫자·밑줄만** 쓴다(한글 이름은 `desc` 에). 교재 기호가 있으면 뜻을 살려 짓고 원래 기호는 `desc` 에 적는다.

교재의 제도 순서에 가장 가까운 kind 를 고르는 것이 요령이다. 같은 점을 여러 방식으로 찍을 수 있지만, 교재가 "옆목점에서 22° 내려 어깨길이만큼" 이라 말했다면 `polar` 로 쓰는 편이 나중에 고칠 때 뜻이 통한다.

#### `xy` — 좌표를 식으로 직접

기준 사각형의 꼭짓점, 원점, 기준선 위의 점처럼 **다른 점을 안 거치고 바로 정해지는 자리**에 쓴다.

```json
{ "id": "SNP", "desc": "앞 옆목점", "kind": "xy", "x": "B/20+NW_ADD", "y": 0 }
```

| 필드 | 뜻 |
|---|---|
| `x` | x 좌표 식 |
| `y` | y 좌표 식 (아래가 +) |

#### `offset` — 다른 점에서 가로·세로 이동

"A 에서 아래로 등길이", "중점을 모서리 쪽으로 0.6 밀어냄" 처럼 **기준점에 매다는** 자리.

```json
{ "id": "CF_W", "desc": "앞중심 허리점", "kind": "offset", "from": "A", "dx": 0, "dy": "WL" }
```

| 필드 | 뜻 |
|---|---|
| `from` | 기준점 id |
| `dx` | 가로 이동 식 |
| `dy` | 세로 이동 식 (아래가 +) |

#### `polar` — 다른 점에서 각도·거리

어깨선처럼 **경사와 길이로 정해지는** 자리.

```json
{ "id": "SH_DIR", "desc": "어깨 경사 방향점", "kind": "polar",
  "from": "SNP", "angle": "-SH_ANGLE", "dist": 20 }
```

| 필드 | 뜻 |
|---|---|
| `from` | 기준점 id |
| `angle` | 각도(도). `0` = 오른쪽, **양수 = 화면상 반시계(위쪽)** |
| `dist` | 거리 식 |

y 가 아래로 + 인 좌표계라 각도 부호가 직관과 뒤집힌다. **어깨경사처럼 오른쪽 아래로 내려가는 방향은 음수각**이다 — 예제가 `"-SH_ANGLE"` 로 쓰는 이유다.

#### `on` — 두 점을 잇는 선 위의 비율 위치

교재의 "n등분한 점", "앞품선 위 어디쯤".

```json
{ "id": "AH_M", "desc": "앞품점 — 암홀이 지나는 자리",
  "kind": "on", "a": "FW_T", "b": "FW_B", "t": 0.65 }
```

| 필드 | 뜻 |
|---|---|
| `a` | 시작점 id (`t = 0` 자리) |
| `b` | 끝점 id (`t = 1` 자리) |
| `t` | 비율 식. 3등분이면 `1/3` 로 써도 된다(식이므로) |

`t` 는 0~1 밖으로 나가도 된다 — 연장선 위의 점이 된다.

#### `intersect` — 두 직선의 교점

"어깨선과 어깨너비선이 만나는 곳" 처럼 교재가 **두 선을 그어 만나게 하는** 자리.

```json
{ "id": "SP", "desc": "어깨끝점 (어깨선 × 어깨너비선)", "kind": "intersect",
  "a1": "SNP", "a2": "SH_DIR", "b1": "SWL_T", "b2": "SWL_B" }
```

| 필드 | 뜻 |
|---|---|
| `a1`, `a2` | 직선 1 을 정하는 두 점 |
| `b1`, `b2` | 직선 2 를 정하는 두 점 |

**선분이 아니라 무한직선의 교점**이다. 네 점이 만드는 선분들이 실제로 겹치지 않아도 교점은 나온다 — 그래서 방향만 잡아 주는 보조점(예제의 `SH_DIR`, `SWL_T`/`SWL_B`)을 대충 멀리 찍어도 된다.

못 푸는 경우는 두 가지고, 오류 메시지가 서로 다르다.

- **평행** — 두 직선이 나란해 만나지 않는다. 판정은 절대 오차가 아니라 **두 방향벡터 길이에 비례한 상대 오차**로 한다. 절대 epsilon 을 쓰면 20cm 짜리 두 선이 1e-10cm 어긋난 것을 "만난다" 고 보고 교점을 아주 먼 곳으로 날려 보내는데, 그 점이 `bbox` 에 들어가면 도면 액자가 통째로 망가진다.
- **퇴화** — `a1`/`a2`(또는 `b1`/`b2`)가 같은 점이라 애초에 직선이 안 된다. 같은 점 이름을 두 번 쓰거나, 식이 우연히 같은 좌표를 내놓았을 때 걸린다.

### 식 문법

`x`, `y`, `dx`, `dy`, `angle`, `dist`, `t` 자리에는 **숫자를 그대로 쓰거나 계산식 문자열**을 쓸 수 있다. 식은 `eval()` 로 돌리지 않는다 — [`lib/expr.mjs`](lib/expr.mjs) 가 자체 토크나이저·파서로 순수 계산만 한다. 식의 출처가 이미지를 읽은 모델이라 임의 코드가 섞여 들어올 수 있기 때문이다.

**연산자** — `+` `-` `*` `/` `%`(나머지) `^`(거듭제곱), 단항 `+`/`-`, 괄호.

우선순위는 `^` > `*` `/` `%` > `+` `-` 이고, `^` 만 우결합이다(`2^3^2 = 512`). **단항 마이너스는 `^` 보다 약하게 묶인다** — 수학·파이썬 관례를 따라 `-2^2` 는 `4` 가 아니라 **`-4`** 다(`-(2^2)` 로 읽는다). 지수 쪽 단항은 그대로 받으므로 `2^-1` 은 `0.5` 다.

`0` 으로 나누면 터진다. `%` 를 `0` 으로 나누는 것도 마찬가지다.

**함수** — 전부 소문자. 17개다:

| 분류 | 함수 | 인자 수 |
|---|---|---|
| 수 | `sqrt` `abs` `round` `floor` `ceil` | 1 |
| | `min` `max` `hypot` | 1개 이상(가변) |
| 삼각 | `sin` `cos` `tan` `asin` `acos` `atan` | 1 |
| | `atan2` | 2 |
| 각 변환 | `rad`(도→라디안) `deg`(라디안→도) | 1 |

**인자 수를 검사한다.** 표에 적힌 수와 다르면 계산 전에 오류가 난다. 특히 `round` 는 **정수 반올림 하나뿐**이라 `round(B/4, 1)` 처럼 소수 자리를 주면 걸린다 — **소수 자리 반올림 기능은 없다.** 자릿수를 맞추고 싶으면 `round(B/4*10)/10` 처럼 직접 쓴다. 안 재고 넘겼다면 여분 인자가 조용히 버려져 틀린 값이 나온다.

**삼각함수는 도(degree) 단위다.** 제도 교재가 "어깨경사 22°" 로 쓰기 때문이다. `sin(30)` 은 `0.5` 이고, `atan2(1,1)` 은 `45` 를 돌려준다. 라디안이 필요하면 `rad()`/`deg()` 로 명시적으로 바꾼다.

**정의역 밖도 오류다.** `sqrt(0-1)`, `asin(2)` 처럼 결과가 NaN 이 되는 계산은 그 자리에서 터진다. 곱셈·거듭제곱이 무한대로 넘치는 것도 같다 — **NaN·Infinity 가 좌표로 새어 나가지 않는다.**

**상수** — `PI`, `E`.

**교재 OCR 표기를 자동으로 흡수한다.** 도면을 읽은 모델은 곱셈에 `×`, 뺄셈에 유니코드 `−`, 전각 괄호를 그대로 써 온다. 여기서 받아 주지 않으면 "알 수 없는 문자" 로 튕겨 사람이 손으로 고쳐야 한다.

| 써 온 것 | 읽는 것 |
|---|---|
| `×` `·` `∙` `＊` | `*` |
| `÷` `／` | `/` |
| `−` `–` `—` `－` | `-` |
| `＋` | `+` |
| `（` `）` | `(` `)` |
| 전각 공백 | 공백 |

그래서 `B×1/2`, `B÷2`, `B−2`, `（B/4）+1` 이 전부 그대로 돈다. 앞자리 없는 소수(`.5`)도 받는다.

**곱셈 기호를 빠뜨리면 원인을 짚어 준다.** `1/3B` 는 교재를 그대로 옮길 때 가장 흔한 실수라, "식 뒤에 군더더기가 남았다 (곱셈 기호 `*` 가 빠진 것 같다)" 로 알려 준다. `1/3*B` 로 고치면 된다.

**한도** — 신뢰할 수 없는 입력이 파서를 터뜨리지 못하게 식 하나는 토큰 2000개, 괄호 100겹까지다.

**다른 점 참조** — `점id.x` / `점id.y` 로 이미 풀린 점의 좌표를 읽을 수 있다.

```json
{ "id": "D_C", "desc": "허리다트 중심 (BP 바로 아래 허리선)",
  "kind": "xy", "x": "BP.x", "y": "WL" }
```

뒤판 예제는 이걸로 "앞어깨보다 `SH_EASE` 만큼 긴 뒤어깨" 를 쓴다:

```json
{ "id": "SP", "desc": "뒤 어깨끝점 (늘림 포함)", "kind": "polar",
  "from": "SNP", "angle": "-SH_ANGLE",
  "dist": "hypot(SP0.x-SNP.x, SP0.y-SNP.y)+SH_EASE" }
```

읽을 수 있는 건 숫자뿐이다(`.desc` 같은 걸 참조하면 "숫자가 아니다" 로 터진다). 점 참조가 있어도 **순서를 신경 쓸 필요는 없다** — 엔진이 의존 관계를 위상정렬해서 풀 수 있는 것부터 푼다. 다만 서로를 참조하는 고리를 만들면 어디서 도는지 이름을 찍어 알려주고 멈춘다.

### segments

점을 잇는 선. `kind` 가 `line` 이냐 `curve` 냐로 갈리고, 둘 다 `id` · `desc` · `layer` 를 갖는다.

```json
{ "id": "waist", "desc": "허리선", "kind": "line", "layer": "cut",
  "pts": ["CF_W", "SIDE_W"], "closed": false }

{ "id": "armhole", "desc": "앞 암홀", "kind": "curve", "layer": "cut",
  "through": ["SP", "AH_M", "SIDE_B"], "tension": 0.42 }
```

| kind | 필드 | 뜻 |
|---|---|---|
| `line` | `pts` | 순서대로 이을 점 id 배열 (2개 이상) |
| | `closed` | 마지막 점을 첫 점과 잇는지 |
| `curve` | `through` | 곡선이 **지나갈** 점 id 배열 (2개 이상) |
| | `tension` | 곡선의 팽팽함 |

곡선은 Freesewing(Brian block) 의 through 곡선과 같은 알고리즘이다 — 기존 패턴 앱들과 결과가 어긋나지 않게 맞춰 두었다. 통과점을 **정말로 지나간다**(근사가 아니다). `tension` 은 `0.42` 가 기본이고, 암홀 `0.42~0.55` · 목선 `0.35~0.45` 가 보통이다. `0` 에 가까울수록 직선이 된다. **`0~2` 밖이면 검사에서 걸린다.**

곡선의 길이는 폴리라인이 아니라 **베지어에서 직접 잰다.** 화면·DXF 로 나갈 때 쓰는 24분할 폴리라인으로 재면 급곡선에서 0.01cm 넘게 짧게 나오는데, 암홀 길이를 소수 둘째 자리까지 보는 도구에서는 그게 그대로 오차가 된다.

`through` 에 같은 점이 연달아 들어오면 그 중복은 걷어내고 곡선을 만든다(퇴화 구간과 길이 0 세그먼트를 막기 위해서다). 다만 **검사기가 먼저 "연달아 두 번 나온다" 로 잡으므로** 정상 경로에서는 볼 일이 없다. `line` 의 `pts` 도 같다.

곡선을 예쁘게 만들려고 통과점을 지어내지 않는 편이 좋다. 교재에 있는 점을 쓰고, 꼭 필요하면 `offset` 으로 조금 밀어낸 보조점을 만들되 `desc` 에 그렇게 적는다(예제의 `NECK_C` 가 그 경우다).

#### layer — 다섯 가지

DSL 의 `layer` 값은 **소문자 다섯 개**뿐이다. DXF 로 나갈 때 **대문자 레이어 이름**으로 바뀐다 — R12 리더 중에 레이어 이름을 대문자로 정규화하는 것이 있어 처음부터 대문자로 쓴다. 대응표는 `lib/dxf.mjs` 의 `DXF_LAYER` 로 export 돼 있다.

| DSL `layer` | 무슨 선인가 | SVG | DXF 레이어 / 선종류 |
|---|---|---|---|
| `cut` | **완성선.** 실제로 재단되는 선 | 검정 실선 | `CUT` / CONTINUOUS |
| `guide` | 안내선·기초선. 기준 사각형, 가슴선, 앞품선 | 회색 점선 | `GUIDE` / DOT |
| `fold` | 골선. 접어서 자르는 중심선 | 파랑 일점쇄선 | `FOLD` / CENTER |
| `dart` | 다트선 | 빨강 실선 | `DART` / CONTINUOUS |
| `construction` | 제도 보조선. 방향만 잡아 주는 선 | 초록 점선 | `CONSTRUCTION` / DOT |

DSL 에서 고를 수 없지만 DXF 파일에는 더 있다. `darts` 는 `layer` 와 무관하게 `DART` 로, `notches` 는 `NOTCH` 로, 도면 이름·점 이름은 `TEXT` 로 나간다. 여기에 DXF 예약 레이어 `0` 을 더해 LAYER 테이블에는 여덟 개가 들어간다(`0` `CUT` `GUIDE` `FOLD` `DART` `CONSTRUCTION` `NOTCH` `TEXT`). 대부분의 리더가 `0` 을 알아서 만들지만 엄격한 CAM 은 그렇지 않아 명시해 둔다.

도면에서 굵은 실선으로 그려진 완성선은 `cut`, 가늘거나 점선인 기초선은 `guide` 로 나눠 담는다. 이 구분은 장식이 아니다 — 조각의 실제 크기(`cutBbox`)를 `cut` 과 `fold` 로만 재고, 검증 스크립트도 `cut` 선만 길이를 잰다.

### darts · notches · notes

```json
"darts": [
  { "id": "waist_dart", "desc": "앞 허리다트", "apex": "BP", "leg1": "D1", "leg2": "D2" }
],
"notches": [
  { "id": "n_shoulder", "desc": "어깨 합인 너치", "at": "SH_N" }
],
"notes": [
  "어깨끝은 어깨경사선과 어깨너비선(SW/2)의 교점으로 잡았다."
]
```

- **darts** — 꼭짓점(`apex`)과 양쪽 다리 끝(`leg1`/`leg2`)을 점 id 로 가리킨다. `leg1 → apex → leg2` 폴리라인으로 그려지고, 벌림(`width`)은 두 다리 끝 사이 거리로 계산해 준다. 다트를 **접거나 회전시키지는 않는다** — 지금은 그리기만 한다.
- **notches** — 점 하나(`at`)를 가리킨다. SVG 는 작은 원, DXF 는 `NOTCH` 레이어의 CIRCLE 로 나간다.
- **notes** — 도면에서 읽어냈지만 구조로 못 담은 것, 추정한 값, 헷갈린 부분을 한 줄씩. 기준 치수가 도면에 없어 표준값을 넣었다면 그 사실을 여기 적는다.

### 좌표계 규약

- **x 는 오른쪽이 +, y 는 아래가 +.** 화면 좌표와 같고, 이 사용자의 다른 패턴 앱들과도 같다.
- **단위는 cm.** 전부.
- 보통 앞중심/뒤중심을 `x = 0` 에, 어깨 수평 기준선을 `y = 0` 에 두고 시작한다(예제가 그렇다).
- 각도는 도(degree). `polar` 의 `0°` 는 오른쪽, 양수는 화면상 위쪽으로 돈다.
- 렌더 결과는 두 가지 바운딩박스를 갖는다. `bbox` 는 보조점·보조선까지 전부 감싼 것(SVG 액자용)이고, `cutBbox` 는 `cut`·`fold` 선과 다트·너치만 감싼 **실제 조각 크기**다. 그레이딩 검증이나 용지 배치는 `cutBbox` 를 봐야 한다 — 보조점 하나가 멀리 떨어져 있으면 `bbox` 는 치수를 따라 자라지 않는다.
- DXF 로 나갈 때는 cm → mm 로 10배 되고 y 부호가 뒤집힌다(DXF 는 y 가 위쪽이다). 엔진 안에서는 신경 쓸 것 없다.

## 도구

### `tools/render.mjs` — DSL → SVG + DXF

```bash
node tools/render.mjs examples/bunka-front.draft.json
node tools/render.mjs examples/bunka-front.draft.json --set B=92 --set WL=39
node tools/render.mjs out/p128.draft.json --out out/p128 --labels
```

| 옵션 | 뜻 |
|---|---|
| `--out <경로>` | 출력 파일 앞부분(확장자 없이). 기본은 `out/<입력파일이름>` |
| `--set 이름=값` | measures/params 값을 덮어쓴다. 여러 번 쓸 수 있다 |
| `--labels` | DXF 에 점 이름을 TEXT 로 넣는다 (기본 꺼짐 — 공장 전달용에는 잡음이다) |
| `--no-points` | SVG 에서 점·이름 표시를 끈다 |
| `--no-title` | DXF 에 도면 이름을 넣지 않는다. 한글 제목이 깨지는 CAM 으로 보낼 때 쓴다 |

플래그는 `--이름 값` 과 `--이름=값` 을 둘 다 받는다. 값을 받는 플래그(`--out` `--set`) 바로 뒤의 토큰은 그 플래그의 값으로만 읽으므로, 파일 이름에 공백이 있어도 `--out out/zz "도 면.json"` 이 제대로 갈린다. **모르는 플래그, 값이 빠진 플래그, 입력 파일을 두 개 준 경우는 종료코드 2 로 거절한다** — 쓰는 사람의 실수와 도면의 오류를 종료코드로 구분한다.

`--set` 은 `이름=값` 꼴이 아니거나, 값이 비었거나, 숫자가 아니면 전부 막는다. `Number('')` 가 `0` 이라 그냥 넘기면 `B=0` 짜리 쓰레기 도면이 조용히 만들어진다.

먼저 `validate` 를 걸고, 오류가 있으면 전부 찍고 멈춘다(반쯤 그린 도면을 내지 않는다). 통과하면 `.svg` 와 `.dxf` 를 쓰고, 조각 크기와 완성선(`cut`) 하나하나의 실측 길이를 찍어 준다 — 암홀·어깨·목선이 상식적인 길이인지 여기서 바로 보인다.

제도·출력에서 나는 오류(`DraftError`·`ExprError`)는 쓰는 사람이 고칠 수 있는 것이라 **스택 대신 한 줄 메시지 + 종료코드 1** 로 낸다. 그 밖의 예외는 엔진 쪽 버그이므로 스택이 그대로 보인다.

SVG 는 cm 좌표를 그대로 쓰고 `viewBox` 만 잡는다. 1cm 모눈과 5cm 자가 들어가므로 원본 사진 위에 겹쳐 배율을 맞추기 쉽다. DXF 는 R12(AC1009) · mm 단위다.

### `tools/extract.mjs` — 이미지 → DSL

```bash
node tools/extract.mjs 교재_128쪽.png --name p128
node tools/extract.mjs 앞판.jpg 뒤판.jpg --name blouse --hint "문화식 블라우스 원형, B=86"
```

| 옵션 | 뜻 |
|---|---|
| `--name <이름>` | 출력 파일 이름. 기본은 첫 이미지 파일 이름 |
| `--hint "<설명>"` | 교재·제도 계열·기준 치수 등 아는 것을 알려 준다 |
| `--effort low\|medium\|high\|xhigh\|max` | 모델의 사고 강도. 기본 `xhigh` |

`render.mjs` 와 같은 규칙으로 인자를 가른다 — `--이름 값` 과 `--이름=값` 을 둘 다 받고, 모르는 플래그·값 빠진 플래그는 종료코드 2 다. `--effort` 는 화이트리스트로 **이미지를 올리기 전에** 막는다. 안 그러면 큰 이미지를 다 전송하고 나서 400 을 받는다. 이미지 개수보다 먼저 보는 이유도 같다 — `--effort 앞판.png` 처럼 값을 빠뜨렸을 때 "이미지가 없다" 보다 "effort 값이 이상하다" 가 실제 실수를 가리킨다.

이미지는 여러 장 줄 수 있다(png · jpg · jpeg · webp · gif). 결과는 `out/<이름>.draft.json` 으로 나간다. **base64 로 부풀린 이미지 합계가 요청 한도(32MB)의 80% 를 넘으면 미리 경고한다** — 장수를 줄이거나 해상도를 낮추라는 뜻이다. 한도를 넘으면 요청 자체가 거부된다.

하는 일은 "그림을 그려줘" 가 아니라 **"제도 절차를 받아써줘"** 다. `lib/schema.mjs` 를 structured output 의 `json_schema` 로 걸어 모델이 DSL 모양을 벗어날 수 없게 하고, 시스템 프롬프트로 좌표 대신 계산식을 쓰도록 못을 박는다. 예제 두 개(`examples/bunka-front` · `bunka-back`)를 문법 참고로 같이 보낸다. `max_tokens` 는 64000 을 준다 — 그 한도가 **thinking 과 응답 텍스트를 합쳐** 재는 값이라 `xhigh` 로 도면을 읽으면 생각만으로도 꽤 쓴다.

받은 결과에 `validate` 를 걸고, **오류가 있으면 그 목록을 그대로 되돌려 한 번 더 시킨다.** 스키마는 구조만 막을 수 있어서(없는 점을 가리키는 것, 인자 수가 틀린 함수 같은 건 스키마로 못 막는다) 이 되돌리기가 필요하다. 두 번째도 실패하면 파일은 남겨 두고 오류를 찍는다 — 손으로 고치면 된다.

끝나면 읽어낸 치수·점 수·조각 크기와 `notes` 를 찍어 준다. **`notes` 를 반드시 읽을 것** — 모델이 못 읽었거나 추정한 자리가 거기 적힌다.

**인증** — 다음 중 하나면 된다:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

또는

```bash
ant auth login
```

### `tools/overlay.mjs` — 원본 위에 겹쳐 보기

DSL 로 뽑은 도면을 교재 사진 위에 반투명으로 얹어, 어디가 어긋났는지 눈으로 찾는 도구다. [파이프라인](#파이프라인)의 되먹임 고리가 여기다 — 이 도구로 재서 고친 결과를 `examples/fewshot/` 에 쌓으면 다음 페이지 인식률이 올라간다.

```bash
node tools/overlay.mjs out/p128.draft.json 교재_128쪽.png
node tools/overlay.mjs out/p128.draft.json 교재_128쪽.png --out out/p128.html --set B=92
```

| 옵션 | 뜻 |
|---|---|
| `--out <경로.html>` | 결과 파일. 기본은 `out/<입력파일이름>.overlay.html` |
| `--set 이름=값` | measures/params 를 덮어쓴 상태로 겹쳐 본다. 여러 번 쓸 수 있다 |

이미지는 `render`·`extract` 와 같은 다섯 가지(png · jpg · jpeg · webp · gif)를 받는다. PDF·TIFF 는 먼저 png 로 바꿔야 한다. 인자 규칙은 세 도구가 같다 — `--이름 값` 과 `--이름=값` 을 둘 다 받고, 모르는 플래그·값 빠진 플래그·파일을 셋 이상 준 경우는 종료코드 2 로 거절한다.

결과는 **외부 의존이 하나도 없는 단일 HTML** 이다 — 사진은 data URI 로, 도면은 인라인 SVG 로 박혀 있다. 파일 하나만 열면 되고, 그대로 다른 사람에게 넘길 수 있다.

브라우저에서 할 수 있는 것:

| 자리 | 하는 일 |
|---|---|
| **보기** | 도면 진하기 · 사진 진하기 · 화면 배율 |
| **도면 맞추기** | 배율 · 가로/세로 이동 · 회전(±10°). 도면 위를 끌면 이동, 휠은 마우스 자리를 축으로 도면 배율, <kbd>Alt</kbd>+휠은 화면 배율, 화살표는 1px(<kbd>Shift</kbd> 10px) |
| **2점 배율 맞추기** | 사진에서 **실제 길이를 아는 두 점**(자 눈금, 방안지 칸)을 클릭하고 그 길이를 cm 로 넣으면 배율이 계산돼 적용된다. 첫 점을 고정하고 배율만 바꾸므로 맞춰 둔 위치가 흐트러지지 않는다. 5cm 자와 눈으로 맞추는 것보다 정확하다 |
| **레이어** | 완성선·안내선·골선·다트·보조선·너치·점 이름·1cm 모눈·5cm 자·도면 흰 배경을 따로 껐다 켠다 (흰 배경은 기본 꺼짐 — 켜면 사진을 덮는다) |
| **변환값** | 지금 맞춘 `scale`·`dx`·`dy`·`rotDeg`·`pxPerCm`·`originCm` 을 JSON 으로 보여주고 복사한다. 다시 손으로 맞출 일이 없다 |
| **완성선 길이** | `cut` 선마다 이름·실측 길이·설명. 선 위에 마우스를 올리면 그 선이 굵어지고 이름·길이가 툴팁으로 뜬다 |

보는 순서는 실행하면 콘솔에도 찍힌다. 2점 배율로 척도를 잡고 → 도면을 끌어 원점(앞중심 × 어깨선)을 사진에 포갠 뒤 → 스캔이 기울었으면 회전으로 잡고 → 어긋난 선의 이름을 확인해 `draft.json` 을 고치고 → 다 맞으면 변환값을 챙겨 둔다.

DSL 오류가 있으면 HTML 을 만들지 않고 오류를 전부 찍고 멈춘다(`render.mjs` 와 같다).

### 검증 스크립트 넷

`npm test` 가 이 넷을 순서대로 돌린다. 각각이 지키는 것이 다르다.

| 스크립트 | 지키는 것 |
|---|---|
| `tools/verify_expr.mjs` | **식 평가기.** 연산자 우선순위·결합(`2^3^2 = 512`, `-2^2 = -4`, `2^-1 = 0.5`), 교재 계산식, 점 참조(`SNP.x`), 도 단위 삼각함수, OCR 표기 흡수(`B×1/2` · `B÷2` · `B−2` · `（B/4）+1` · `.5`). 오류 쪽이 더 촘촘하다 — 0 나눗셈·0 나머지, 인자 수(`round(2.55, 1)` · `atan2(1)` · `min()`), 정의역 밖(`sqrt(0-1)` · `asin(2)`), 프로토타입 이름(`constructor` · `toString(1)` · `valueOf`), 토큰·괄호 한도, 곱셈 기호 누락 힌트(`1/3B`), 그리고 `B; process.exit(1)` 이 통과하지 않는다는 것(= `eval` 이 아니라는 것) |
| `tools/verify_draft.mjs` | **DSL 해석.** 예제 좌표를 손계산 값과 대조하고, 곡선이 양 끝점을 정확히 지나는지 재고, **암홀·목선 길이와 암홀 중간점을 소수 셋째 자리까지 못 박는다**(길이 밴드만 두면 `tension` 을 바꾸거나 곡선을 직선으로 만들어도 통과해 곡선 기하가 사실상 미검증이 된다). 그리고 잘못된 DSL 을 걷어내는지 — 없는 점 참조 · id 중복(points/segments/notches) · 없는 레이어 · 필수 항목 누락 · 점 1개짜리 선 · 같은 점을 두 번 이은 선 · `tension` 폭주 · 빈 도면 · 잘못된 식(괄호 · 빈 식 · 모르는 이름 · 인자 수 · 코드처럼 생긴 식) · 프로토타입 키(`toString`·`constructor`)를 항목으로 밀어넣기 · 참조 고리 · 평행선 교점. 치수 이름이 `toString` 이어도 선언값이 이기는지도 본다 |
| `tools/verify_grade.mjs` | **그레이딩 — 이 엔진의 존재 이유.** 44~88호 다섯 사이즈로 다시 풀어서, `cutBbox` 폭·높이와 암홀·어깨·목선이 전부 **단조 증가**하는지, 44→88 폭 증가가 `B/4` 기준(반폭 도면이므로 5cm)과 맞는지, 완성선 길이가 전부 유한한 양수이고 좌표에 NaN 이 없는지, 앞뒤 암홀 합이 원형 범위(32~50cm)에 드는지. 여기서 무너지면 "식이 아니라 숫자를 박아 넣었다" 는 뜻이다 |
| `tools/verify_dxf.mjs` | **DXF 가 CAD 에서 열린다는 것.** AC1009 선언 · CRLF · EOF · 그룹코드/값 짝 · `LWPOLYLINE` 이 안 들어갔는지 · STYLE 테이블에 `STANDARD` 가 있는지 · LTYPE 셋이 다 있고 **각 LTYPE 의 40(무늬 전체 길이)이 49 요소 절대값 합과 맞는지** · 엔티티가 쓰는 레이어가 전부 LAYER 테이블에 있고 예약 레이어 `0` 도 있는지 · POLYLINE/CIRCLE/TEXT 개수와 POLYLINE 마다 VERTEX 가 2개 이상 붙었는지 · **도면 이름에 개행을 넣어도 파일이 안 깨지는지** · `--labels` 없이는 점 이름이 안 나가고 `title: false` 면 TEXT 가 아예 없는지 · `$EXTMIN/$EXTMAX` 가 제목 TEXT 까지 감싸는지 · `parseDXF` 가 SEQEND 뒤 떠돌이 VERTEX 를 폴리라인에 붙이지 않는지 |

좌표 검사는 **ENTITIES 의 VERTEX 만** 골라서 한다. 파일 전체에서 그룹코드 10/20 을 긁으면 `$EXTMIN/$EXTMAX` 헤더 값과 POLYLINE 더미 좌표(`0.0`)가 섞여 들어와, y 부호 뒤집기를 통째로 없애도 검사가 통과해 버린다(실제로 그랬다). 그래서 cm→mm 배율(x 폭이 10배)과 y 뒤집기(엔진에서 아래쪽인 허리선이 DXF 에서 가장 작은 y)를 그 정점들만으로 잰다.

`verify_grade` 는 사이즈별 실측표를 찍어 준다. 값이 이상하면 통과하더라도 눈에 띈다.

## few-shot 으로 인식률 올리기

`examples/fewshot/` 에 **이미지와 같은 이름의 `.draft.json` 을 짝으로** 넣어 두면, `extract.mjs` 가 실행할 때마다 자동으로 찾아 few-shot 예시로 실어 보낸다.

```
examples/fewshot/
  p128.png
  p128.draft.json      ← 같은 이름
  p130.jpg
  p130.draft.json
```

짝이 없는 이미지는 **경고를 찍고** 건너뛴다 — 조용히 빠지면 "예시를 넣었는데 왜 안 나아지지" 를 한참 헤맨다. 이미지 없는 json 은 그냥 무시하고, 폴더가 비어 있어도 아무 일도 안 일어난다.

싣는 순서는 **파일 이름 순으로 고정**한다. 요청 앞부분이 매번 같아야 프롬프트 캐시가 살아 있다.

**오버레이로 고쳐 놓은 결과를 여기 쌓을수록 다음 페이지 인식률이 올라간다.** 같은 교재의 다른 쪽을 뽑을 때 특히 그렇다 — 그 교재의 기호 붙이는 법, 곡선 통과점 잡는 버릇, 어떤 값을 `params` 로 빼는지를 예시에서 그대로 배워 간다. 손으로 한 번 고친 일이 다음 판에 남는 유일한 자리다.

## 예제에 관하여

`examples/bunka-front.draft.json` · `bunka-back.draft.json` 은 **데모 픽스처이지 특정 교재의 전사본이 아니다.** 문화식 계열 계산식을 본떠 DSL 문법과 검증 스크립트가 돌아갈 만큼 만들어 둔 것이고, 파일 안 `source.book` 과 `notes` 에도 그렇게 적혀 있다. 제도값을 실무에 그대로 쓸 물건이 아니다.

실제 교재 페이지는 `tools/extract.mjs` 로 뽑아 이 자리를 대체하는 것이 원래 쓰임새다.

다만 이 두 파일은 검증 스크립트 셋(`verify_draft` · `verify_grade` · `verify_dxf`)의 고정 픽스처이기도 하다 — 점 이름(`SNP`, `SP`, `BP`…)과 선 이름(`armhole`, `shoulder`, `neck`)을 손계산 값과 함께 직접 대조한다. 고치면 그 검증들도 같이 고쳐야 한다.

## 알려진 한계 · 앞으로 할 것

**인식**

- `extract.mjs` 의 정확도를 보증하지 않는다. 곡선의 통과점 위치, 어떤 숫자가 상수이고 어떤 것이 식의 일부인지, 겹쳐 그린 앞뒤판의 구분 — 이런 곳에서 틀린다. 오버레이로 재서 고치는 루프를 전제로 만든 도구다.
- 한 번에 조각 하나만 뽑는다. 한 장에 앞·뒤판이 같이 있으면 조각별로 나눠 호출해야 한다.
- 소매·칼라처럼 몸판에서 유도되는 조각(암홀 길이를 재서 소매산을 그리는 식)은 다루지 못한다. DSL 이 다른 파일의 도형을 참조할 방법이 없다.

**DSL·엔진**

- 조각 사이의 관계가 없다. 앞판 암홀과 뒤판 암홀이 소매와 맞는지 같은 **맞물림 검증은 이 리포의 일이 아니다** — `pattern-sewability-verify` 스킬 쪽 일이다. `verify_grade` 가 앞뒤 암홀 합을 상식 범위로만 훑는 것이 전부다.
- **시접이 없다.** 완성선만 그린다.
- **다트를 접지 않는다.** `darts` 는 다리와 꼭짓점을 그리기만 하고, 다트를 회전시키거나 완성선에서 쐐기를 빼내지 않는다.
- 곡선의 시작·끝 접선 방향을 DSL 에서 지정할 수 없다. `lib/curve.mjs` 의 `through()` 는 받을 수 있지만 스키마에 뚫려 있지 않아, 지금은 통과점을 더해 모양을 잡는 수밖에 없다.
- 조각 배치(네스팅)·A4 1:1 타일 인쇄가 없다. SVG 는 조각 하나를 액자에 담을 뿐이다.
- 스키마에 선택 항목이 없어 DSL 이 장황하다. structured output 제약을 그대로 받은 결과다.
- 식 평가기는 한글 식별자를 읽을 수 있지만 `validate` 가 영문 id 만 허용한다 — 실질적으로 영문만 쓸 수 있다.
- 식에 **소수 자리 반올림이 없다.** `round` 는 정수 반올림 하나뿐이라 `round(B/4, 1)` 은 오류다. 필요하면 `round(B/4*10)/10` 처럼 직접 쓴다.

**출력**

- DXF 는 POLYLINE(직선 근사)로만 나간다. 곡선을 구간마다 24등분해 펴서 내보내므로 CAD 에서 베지어로 다시 잡히지 않는다. (길이 표시는 폴리라인이 아니라 베지어에서 재므로 도면 위 숫자는 정확하다.)
- 너치는 원(CIRCLE)으로만 표시한다. 업계에서 쓰는 V 노치·슬릿 모양이 아니다.
- **DXF 제목에 한글이 들어가면 구형 CAM 에서 깨진다.** R12 의 `STANDARD` 폰트(`txt.shx`)에 한글 글리프가 없기 때문이다. 그런 곳으로 보낼 때는 `render.mjs --no-title`(라이브러리로는 `toDXF(drawing, { title: false })`)로 제목 TEXT 를 끄면 되고, 도면 이름은 파일 맨 앞 999 주석에 그대로 남는다. `--labels` 로 넣는 점 이름은 영문 id 라 이 문제가 없다.
- `tools/overlay.mjs` 의 맞추기는 **상사변환(배율 · 이동 · 회전)까지**다. 렌즈 왜곡이나 책을 펼쳐 찍어 생긴 사다리꼴 일그러짐은 못 편다. 그런 사진은 스캔으로 다시 받거나, 도면의 한 구역씩 나눠 맞춰 봐야 한다. 회전도 ±10° 까지만 준다 — 스캔 기울기를 잡는 용도라서다.
- 오버레이에서 맞춘 변환값은 **복사해 두는 것까지**가 전부다. 그 값을 받아 자동으로 정합하거나 도면을 고쳐 주는 단계는 아직 없다.
